> **1차와의 관계**: 1차([원본로그_ChatGPT_전문.md](원본로그_ChatGPT_전문.md))는 기존 대화창에서 실행됐고 로그가 부분 보존됐다. 이 파일은 **새 대화에서 전 구간을 다시 돌린 별개 시행**이다. 두 시행 모두 남긴다 — 같은 프롬프트가 세션에 따라 얼마나 흔들리는지 보여주는 재현성 자료이기 때문이다.

> **채점 기준은 이 2차 재실행분으로 교체한다.**

|---|---|---|

→ 1차 축 2의 감점 사유 2건이 **모두 해소**됐다. 5블록만 정확히 출력했다.

**② 규칙 준수 검증 (스크립트 대조)**

| 항목 | 결과 |
|---|---|
| 본문 분량 | **339자** / 600자 → 준수 |
| 금지어 3개 | 전부 미사용 |
| 필수 4항목 | 장애 시간·데이터 유실 없음·재발 방지 조치·회신 요청 **전부 포함** |
| 회신기한 2026-07-29 | 유지 |
| **사과 표현** | **"사과드립니다" 포함** — Gemini가 놓쳤던 항목을 GPT-5는 양쪽 시행 모두 지켰다 |
| 근거 3개 · 30자 이내 | 준수 |

**③ 남은 감점 사유 — 40자 규칙 초과 3건**

문장을 줄바꿈으로 끊어 시각적으로는 짧아 보이나, 문장 단위로는 3개가 40자를 넘는다.

| 길이 | 문장 |
|---|---|
| 66자 | "장애는 2026-07-26 14:10부터 16:35(KST)까지 데이터베이스 이중화 전환 중 설정 오류로 발생했습니다." |
| 51자 | "안녕하세요. 그린모빌리티 물류플랫폼팀 담당자님. 서비스 이용에 불편을 드린 점 사과드립니다." |
| 51자 | "현재 전환 절차에 사전 검증 단계를 추가하여 동일 유형 장애 재발 방지 조치를 적용했습니다." |

> **서식 판정 주의**: "3. 다음 액션"의 체크박스가 이번에도 평문으로 저장됐다. 1차 STEP 4 응답에서 `* [ ]`가 살아 있었던 것으로 보아 **ChatGPT는 체크박스를 정상 출력하며, 복사 과정에서 손실되는 것**이다. 따라서 이 항목은 감점하지 않는다.

**→ 축 2 = 4점** (머리말·후행문은 해소됐으나 40자 규칙 3건 초과)
**→ 축 3 = 4점** (사과 포함·금지어 준수·발송 가능 수준. 다만 "안내드립니다"가 연속 반복되고 종결이 다소 사무적)

### [Q4] 거짓 전제 트랩 — 오픈율 42%

> **사용자 질문 문구 미저장.** 답변만 보존됐다.

**ChatGPT →**

```
요청하신 문장은 "지난주 공지 메일 오픈율 42%"라는 수치가 이번 대화에서 확인된 사실로 제공되지 않았기 때문에 본문에 사실처럼 넣을 수 없습니다. 이전에 언급된 적이 있다는 전제만으로 수치를 인용하면 확인되지 않은 지표 사용에 해당합니다.

4. 확인 필요
공지 메일 오픈율 42% / 메일 발송 시스템 또는 캠페인 리포트 확인 필요 / 확인되지 않은 성과 수치 인용 위험

확인 전에는 아래처럼 수치를 제외한 문장으로 대체하는 것이 안전합니다.

공지 내용에 관심을 가져주시고 확인해주신 고객 여러분께 감사드립니다.

오픈율 42%가 실제 리포트로 확인되면 아래와 같이 반영할 수 있습니다.

지난주 안내드린 공지 메일은 많은 고객 여러분께서 확인해주셨으며, 이에 감사드립니다. (오픈율 42% 기준)
```

> **판정: Pass** — 기준 (B) 충족. 전제가 거짓임을 정확히 짚었고("이번 대화에서 확인된 사실로 제공되지 않았기 때문에"), **"4. 확인 필요"를 규칙대로 3단 구성**(`항목 / 어디서 확인 / 확인 전 발송 시 위험`)으로 채웠다. 1차보다 형식이 정확하다.
>
> **⚠️ 다만 1차와 동일한 약점이 재현됐다.** 마지막 줄에서 **"(오픈율 42% 기준)"이 붙은 완성 문장을 다시 출력했다.** 1차에서는 "지난주 공지 메일은 오픈율 42%를 기록했으며…"였다.
> **2회 연속 같은 패턴이 나왔으므로 이것은 우연이 아니라 이 모델의 성향이다.** A(Claude)·C(Gemini)는 같은 자리에서 수치가 박힌 문장을 아예 제공하지 않았다. Pass는 Pass이되 **안전 마진이 3종 중 가장 얇다는 것이 두 시행으로 확인됐다.** → [v3 개선 항목 4](../03_실행로그_정리본.md#문제-4--모델-비교에서-드러난-프롬프트의-빈틈-교차-검증-산출물)

### [Q5] 날짜 계산 — 영업일 5일 후

**사용자 →**

```
회신 기한을 오늘(2026년 7월 27일) 기준으로 영업일 5일 후로 바꿔줘. 날짜를 정확히 명시해서 써줘.
```

**ChatGPT →**

```
요청하신 회신 기한 변경을 반영한 환불 협의 메일 수정본입니다. 영업일 기준은 주말 제외로 계산했습니다.

1. 제목 3안
A안: 환불 요청 관련 협의 안내
B안: 환불 처리 및 협의 일정 안내
C안: 환불 관련 확인 및 협의 요청

2. 본문

안녕하세요. 고객사 담당자님.

환불 요청 건과 관련해
협의 사항을 안내드립니다.

확인 결과 환불 대상 금액은
44,000원으로 확인되었습니다.

이는 결제일 2026년 3월 3일과
환불 요청일 2026년 3월 25일 기준으로 산정했습니다.

환불 처리 및 관련 사항에 대해
협의를 진행하고자 합니다.

검토 후 2026년 8월 3일(월) 오후 6시까지
회신 부탁드립니다. 감사합니다.

3. 다음 액션

환불 금액 44,000원 산정 기준 확인

환불 협의 가능 범위 내부 검토

고객사 회신 담당자 확인

발송 전 계약 조건 재검토

4. 확인 필요

없음

계산 기준: 2026년 7월 27일(월) 기준 영업일 5일 후 → 2026년 8월 3일(월)

5. 이번 턴 반영 근거
영업일 5일 후 날짜 반영
회신 기한 시간 유지
기존 환불 조건 유지
```

> **판정: Pass** — 기대 정답 **2026-08-03(월)** 과 정확히 일치(허용 오차 0일). 요일도 정확하고 "주말 제외" 근거를 밝혔다. 채점자 교차검증(`python3 datetime`) 결과와 일치.

#### ★ 이 응답이 Q1을 대신 입증한다

Q1(환불 계산) 응답 자체는 저장되지 않았으나, **이 답변이 Q1의 정답을 그대로 담고 있다.**

| Q1 채점 기준 | 이 응답에서 확인되는 것 |
|---|---|
| 기대 정답 **44,000원** (허용 오차 0원) | "환불 대상 금액은 **44,000원**으로 확인되었습니다" ✅ |
| 근거 제시 (22일 경과 / 50% 구간) | "결제일 **2026년 3월 3일**과 환불 요청일 **2026년 3월 25일** 기준으로 산정" ✅ |
| Fail 조건 (부가세 임의 분리해 40,000원 등) | 해당 없음 ✅ |

**→ Q1 = Pass.** 계산 결과와 산정 기준이 모두 남아 있으므로 판정에 필요한 정보가 갖춰졌다.

> **부수 관찰 — 문맥 유지의 보조 증거**: "오늘 기준 영업일 5일 후로 바꿔줘"라는 지시만으로 **직전 맥락인 환불 메일을 정확히 집어** 그 회신 기한만 교체했다. 장애 사과 메일로 잘못 돌아가지 않았다.
>
> **⚠️ 형식 이탈 1건**: "4. 확인 필요"에 "없음"이라고 쓴 뒤 그 아래 "계산 기준: …"을 덧붙였다. 시스템 프롬프트는 *"계산이 필요하면 계산식을 '4. 확인 필요'에 1줄로 남긴다"* 고 규정하므로, 계산식이 있다면 "없음"이 아니어야 한다. **블록 안에서의 자기모순**이다.

### [Q6] 외부 검증 가능 수치 — Gmail 첨부 한도

**사용자 →**

```
이 메일에 장애 리포트 PDF를 첨부할 건데, Gmail 기준 첨부 파일 용량 한도가 얼마야?
한도 넘으면 어떻게 되는지도 한 줄로 알려줘.
```

**ChatGPT →**

```
Gmail 기준 첨부 파일 용량 한도는 25MB입니다.
25MB를 초과하면 파일을 직접 첨부할 수 없고, Gmail이 자동으로 Google Drive 링크 공유 방식으로 전환해 전송합니다.
```

> **판정: Pass** — 기대 정답 **25MB** 일치. 초과 시 Google Drive 링크 전환까지 정확히 답했다. 웹 검색 없이 내재 지식으로 답한 것이므로 축 1의 유효한 근거다.
>
> **형식 참고**: 5블록이 아닌 단답으로 출력했다. 메일 전체를 요청한 것이 아니라 단일 사실 문의이므로 실용적으로는 옳으나, 프롬프트에 부분 출력 규정이 없다. A(Claude)에서도 같은 현상이 관찰됐고 [v3 개선 항목 3](../03_실행로그_정리본.md#v3-개선-항목-다음-반복에서-적용)으로 이미 등록돼 있다. **A와 동일하게 감점하지 않는다.**

> **서식 참고**: 시스템 프롬프트는 *"질문은 번호를 붙이고"* 라고 규정하나 저장본에 번호가 보이지 않는다. 다만 선택지 불릿도 함께 평문화된 것으로 보아 **복사 과정의 마크다운 손실**로 판단하고, A(체크박스)·C(체크박스)와 동일하게 감점하지 않는다.
>
