# QA — 「결」 회차 검사

실제 브라우저(헤드리스 크롬)를 CDP 로 조작해 전 기능을 검사하고,
회차마다 보고서와 이력을 남긴다.

화면을 거치지 않는 단위 테스트로는 "⌘K 가 크롬 주소창에 먹히는가",
"좁은 화면에서 가로 스크롤이 생기는가" 같은 것을 잡을 수 없다.
그래서 QA 는 반드시 브라우저를 통과시킨다.

## 실행

```bash
node qa/run.mjs                 # 전체
node qa/run.mjs --only 기능      # 특정 영역만
node qa/copy.test.mjs           # 문구 규칙의 회귀 테스트
```

개발 서버가 떠 있지 않으면 알아서 띄운다. 크롬도 알아서 띄운다.
API 를 실제로 호출하므로 `.env` 에 키가 있어야 한다.

종료 코드는 실패나 문구 오류가 있으면 1 이다.

## 남는 것

```
qa/reports/<회차>.md     회차 보고서 (사실 + 에이전트가 쓴 해석)
qa/history.jsonl         회차별 한 줄 — 통과 수, 소요 시간, 지표
```

`history.jsonl` 이 쌓여야 "언제부터 깨졌나", "느려지고 있나"를 볼 수 있다.
보고서는 직전 회차와의 차이(회귀·복구·신규)를 자동으로 붙인다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `run.mjs` | 회차 실행기. **사실만** 기록한다 |
| `harness.mjs` | 브라우저 조작 (키 입력, 뷰포트, 콘솔·네트워크 수집) |
| `checks.mjs` | 검사 목록. 하나가 `{ id, area, title, run }` |
| `copy.mjs` | 화면 문구 검사 규칙 |
| `copy.test.mjs` | 문구 규칙 자체의 회귀 테스트 |

해석과 개선 제안은 실행기가 쓰지 않는다. `gyeol-qa` 에이전트가
보고서의 빈 칸("해석과 제안")을 채운다.

## 검사를 추가할 때

`checks.mjs` 에 항목을 더한다.

```js
{
  id: 'area.name',
  area: '기능',
  title: '사람이 읽을 한 줄',
  async run(ctx) {
    // ctx.js / ctx.key / ctx.viewport / ctx.goto 를 쓴다
    return { pass: true, detail: '관찰값', evidence: { ms: 120 } };
  },
}
```

`detail` 에는 통과/실패가 아니라 **관찰한 값**을 적는다.
회차 비교에서 "언제부터 느려졌나"를 보려면 수치가 남아야 한다.
`evidence` 는 `history.jsonl` 의 `metrics` 로 들어간다.

## 문구 규칙을 고칠 때

오탐을 발견하면 규칙에 `unless` 조건을 붙이고 **반드시**
`copy.test.mjs` 에 케이스를 추가한다.

실제로 있었던 오탐:

- `교정하지 않고` — 이 제품이 **하지 않는** 일을 밝히는 문장이라 옳다
- `엔드포인트 설정` — 3층 구조 표의 층 이름이지 UI 라벨이 아니다
- `할수있습니다` — 겹치는 규칙 셋이 한 오류를 3건으로 부풀렸다
