## 제출 상태 — 3종 채점 완료

| 모델 | 원본 로그 | 합계 |
|---|---|:--:|
| **A. Claude Opus 5** | 3개 파일 (14턴 전문) | **27** |
| **B. GPT-5** | 2개 파일 (1차 + 2차 재실행) | **26** ⚠️ |
| **C. Gemini** | 1개 파일 (12턴) | **27** |

**잠정 선정: A. Claude Opus 5** — A·C 27점 동점이라 실패 비용으로 갈랐다. 근거는 [보고서 5장](01_모델비교선정보고서.md#5-최종-선정-결론).

### 그런데 이 비교의 진짜 결과는 순위가 아니다

**축 1~5에서 세 모델의 점수가 완전히 같다** (5·4·4·5·5). 가중치 ★★★인 축 세 개가 전부 동점이고, **환각 검증은 3종 모두 6/6 Pass**로 18개 판정 중 Fail이 0건이다. 순위를 만든 것은 가중치가 가장 낮은 **축 6 하나뿐**이다.

즉 **이 과업에서 모델 선택은 결정 변수가 아니었다.** [v1 대조 실험](logs/원본로그_v1대조_전문.md)이 이유를 보여준다 — 같은 모델·같은 입력에서 프롬프트만 낮췄더니 "보상 방안을 검토 중"이라는 없는 사실이 생성됐다. 결과를 좌우한 것은 모델이 아니라 프롬프트다.

### 남은 작업 1건 — 한 줄이면 된다

**B 실행 중 오류·재시도·한도 초과가 있었는지, 응답이 느렸는지.**

축 6의 B 점수 3은 **측정된 값이 아니라** "무료 플랜에 한도가 있다"는 요금제 특성만으로 배정한 잠정값이다. 이 한 줄이 1위를 바꿀 수 있다.

| 축 6 | B 합계 | 결과 |
|:--:|:--:|---|
| 3 (현재 잠정) | 26 | 3위 |
| **4** (오류 0회면 루브릭상 이 값) | **27** | **3자 동점 → 무료인 B가 실질 1순위** |

### 함께 확인할 것 2건 (C)

- **모델명** `Gemini 1.5 Pro` — [read.md](read.md) 55행의 과제 **예시 문구**와 글자까지 일치한다. AI Studio 모델 선택기 표기와 대조할 것
- **실행일** `2026-07-28` — A·B(07-27)보다 하루 뒤다

## 이 패키지에서 실제로 사고가 난 지점 2건 — 남겨 두는 이유

**① C의 점수가 한 번 뒤집혔다 (29 → 27).** 처음에는 Gemini가 **스스로 매긴** 29/30점(6축 중 5축 만점, 약점란 "발견되지 않음")이 보고서에 실려 있었고 원본 로그는 없었다. 로그가 저장된 뒤 사람이 같은 루브릭으로 다시 읽자 27점이 됐고, 자기평가가 놓친 결함이 드러났다 — **사과 메일에 사과 표현이 하나도 없었다.** 문자열 검색 한 번이면 나오는 것이었다.

**② B는 실행을 다 하고도 로그를 두 번 잃었다.** 1차·2차 모두 대화 전체를 드래그 복사하다 중간 구간이 누락됐다(2차는 앞 2개 + 뒤 3개만 남고 가운데 5개가 통째로 소실). 긴 대화는 화면 밖 메시지가 DOM에 없어 선택되지 않기 때문으로 보인다. **두 시행을 합쳐서야 6개 축이 채워졌다.**

교훈은 둘이다. **모델에게 자기 채점을 시키지 않는다** — 결함을 찾는 눈이 결함을 만든 눈과 같으면 결함이 보이지 않는다. **점수보다 로그를 먼저 저장한다** — 응답별 복사 버튼을 쓰고, 드래그 복사를 믿지 않는다.

### 이 기록에 함께 남기는 한계 4가지

1. **채널이 셋 다 다르다.** A는 CLI, B는 소비자 웹 UI, C는 AI Studio다. 따라서 **축 6(속도·안정성·비용)은 모델 간 직접 비교가 성립하지 않는다.**
2. **재현성 수준 자체가 모델마다 다르다.** C만 temperature·top_p를 고정할 수 있었고 A·B는 고정 불가다. 즉 C만 재실행 시 동일 조건 재현이 가능하다.
3. **A는 검증자와 같은 세션에서 실행됐다.** 관찰자 편향의 여지가 있으며, 특히 환각 문항 Q1(금액)·Q5(날짜)는 질문지 작성 시 정답을 이미 계산해 둔 상태였다. 자세한 내용은 [환각검증 원본로그](logs/원본로그_환각검증_전문.md) 상단 참조.
4. **C의 점수는 처음에 피평가 모델의 자기평가였다.** 원본 로그가 저장된 뒤 사람이 재채점해 29점 → 27점이 됐다. 경위는 [보고서 3.6절](01_모델비교선정보고서.md#36-점수-근거--c-gemini--실측-제3자-재채점) 참조.
5. **B는 2회 시행을 합쳐 채점했다.** 1차·2차 모두 복사 누락이 있어 단일 시행으로는 6개 축이 차지 않았다. 두 시행은 별개 세션이므로 **엄밀히는 단일 조건 실행이 아니다.**

## 5. 이 패키지의 한 줄 요약

> **v1 대조 실험이 이 패키지의 핵심이다.**
> 같은 모델, 같은 입력인데 프롬프트만 바꿨더니 v1은 "보상 방안을 검토 중"이라는 **없는 사실**을 만들어 냈고, v2는 같은 자리를 `[보상 방안 확인 후 기입]` 자리표시자와 "확인 필요" 블록으로 처리했다.
>
> 프롬프트 엔지니어링이 하는 일은 모델을 똑똑하게 만드는 것이 아니라, **모델이 모른다고 말할 자리를 미리 만들어 두는 것**이다.
